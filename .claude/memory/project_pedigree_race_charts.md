Follow-up to [[project_pedigree_reproduction]], same session. User asked for 4 things: (1) breed standard PDF access from the fiche, (2) richer info when entering a LOF/LOMAD number, (3) a more readable pedigree tree, (4) better charts ("changer de librairie ?").

**Breed standard link**: scraped the full breed directory from `centrale-canine.fr/toutes-nos-races-de-chiens` (390 name→slug pairs, real data not guessed) into `CENTRALE_CANINE_BREED_SLUGS` in `app.js`, matched against `animal.race` via the existing `protectionKey()` normalizer (accent/case-insensitive). Links to the breed's page (`/le-chien-de-race/<slug>`), not directly to the PDF — the PDF URL needs an FCI number (`/sites/default/files/fci_race/<n>.pdf`) not present in the directory listing, but every breed page reliably has a "Télécharger le Standard" button, so one extra click is the honest tradeoff vs. hardcoding ~390 FCI numbers I'd have to source separately.

**LOF/LOMAD lookup**: LOF Select's dog-search-by-number is public and deep-linkable — confirmed the URL pattern by actually submitting the form (`https://www.centrale-canine.fr/lofselect/recherche-chien/identifiant?numLof=<n>`). Added a "Vérifier sur LOF Select" link next to the registry number, shown only when `registry === 'LOF'`. Only the part of `registryNumber` before the `/` is sent (the field stores "n° de portée/année" per `LOF_PATTERN`, LOF Select's plain numeric field is likely a different identifier — noted as an honest guess in a code comment, not a guaranteed match). **No LOMAD equivalent exists**: ACYM's site (see [[project_pedigree_reproduction]]) has no public per-dog lookup, only login-gated declaration forms — did not fake one.

**Pedigree tree**: real SVG connector lines between generations (two small per-branch V-shaped connectors GP→parent, one wider one branches→subject), all with fixed-percentage viewBox coordinates — no runtime DOM measurement, so it's robust to any screen size. Hidden on the existing mobile stacking breakpoint where the wide connector's geometry stops making sense. **Real bug found while doing this**: `#pedigree-card` didn't exist anywhere in the redesigned `index.html` — `renderPedigree()` (and thus the whole pedigree tree, registry badge, health notes) was silently unreachable since the redesign, exactly the same class of gap as the `editPedigree` button fix from the previous session. Added the container to `index.html`'s identity layout and wired `renderFicheV1()` to call `renderPedigree()`.

**Charts**: vendored Chart.js 4.5.1 UMD (`vendor/chart.umd.js`, same treatment as `vendor/qrcode.min.js` — copied as-is by the build, precached in `sw.js`, bumped `CACHE_NAME` to v9). Replaced 4 near-duplicate hand-rolled SVG chart functions with one `drawMetricChart()` + the existing `renderWeightEvolution()`/`renderHeightEvolution()` (now accept an optional `targetId` so the same data can render into two different DOM locations — the frise's "Poids & taille" filter and the dedicated "Poids" tab — without the old innerHTML-copy hack, which would have silently broken with canvases since a cloned canvas node loses its drawing). Also deleted `renderPetProfileWeightChart`/`renderPetProfileHeightChart` and their call site: confirmed 100% dead code (targeted `#pet-profile-weight-chart` etc., which don't exist in the redesigned markup either — same "left behind by the redesign" pattern again).

Two things worth knowing if this breaks again:
- **No date adapter vendored** (`chartjs-adapter-date-fns` etc.) — Chart.js's `type: 'time'` scale needs one and would silently fail without it. Used `type: 'linear'` on epoch-ms timestamps instead with manual tick/tooltip date formatting — gives the same proportional time-spacing (irregular weigh-ins are no longer plotted as if evenly spaced, which the old SVG charts got wrong) with zero extra dependency.
- **Chart.js bakes colors into the canvas at draw time**, unlike the old inline-SVG charts which read `var(--teal)` live — so a theme switch alone doesn't recolor an already-drawn chart. Fixed via `CHART_TARGETS` (containerId → 'weight'|'height') + `redrawChartsForTheme()`, called from both `applyTheme()` and the `setTheme('auto')` branch. If a new chart-consuming feature is added, remember it needs the same re-render-on-theme-change wiring — CSS alone won't do it anymore.

**Verified 2026-09-25**: breed link and LOF Select link generate the exact real URLs (checked against the live site); pedigree tree renders with visible connectors and legible dark AND light theme; weight/height charts render correctly in both the frise and the Poids tab simultaneously (distinct canvas ids, confirmed no collision) with working native tooltips and correct non-uniform time spacing; theme toggle correctly redraws already-open charts. `npm run lint`/`build` clean throughout.
