Built after analyzing two reference sites at the user's request: LOF Select (French kennel club — genetic/health test panels, show/work titles, virtual-alliance mate simulator — the "professional selection" layer) and ACYM Madagascar (the official administrative workflow: déclaration de saillie within 4 weeks, déclaration de naissance within 4 weeks, LOMAD registration within 24 weeks, each with required photos/fees). Scoped down to what fits a personal carnet app: the ACYM-style dated-deadline workflow, plus a simplified free-text version of LOF Select's health/DNA panel (not its full breed-specific taxonomy — that would need a whole reference database of its own).

**Data model:** new `matings` table (child of `pets`, same `CHILD_ARRAYS` pattern as vaccines/medications — added to `backend/api/_lib/mapping.js`, automatically wired into `sync/push`, `sync/pull` since those loops are generic over `CHILD_ARRAYS`). One record per saillie, works for both sexes (role — étalon/lice — is derived from `pets.sex`, not stored): date, method, partner identity (name/owner/registry, free text — not linked to another pet, since the partner usually isn't in this user's carnet), then optional outcome fields (birth_date, live_born, still_born) and three declaration-date fields (declared_at, birth_declared_at, lomad_declared_at) filled in as the user marks each step done. `pedigree` table gained 4 grandparent registry-number columns (previously name-only) and a free-text `health_notes` column.

**Deadline logic** (`matingNextDeadline()`, duplicated client/server like every other reminder type in this app — `frontend/app.js` and `backend/api/_lib/reminders.js`'s `nextMatingDeadline()`, kept in sync by hand): collapses to the single most urgent open deadline (declare saillie → declare naissance → LOMAD registration), each computed from `date`/`birth_date` + a fixed day offset (28/28/168). Feeds into the same generic due-item machinery vaccines/medications use (`collectDueItemsForAnimal`, `completeDueItem`, home-page urgency banner, alerts tab, frise) — but with "Reporter" suppressed everywhere for matings (legal deadlines can't be snoozed, only marked done) and the home banner's "Appeler la clinique" replaced with "Voir la fiche" → navigates to the Reproduction tab.

**New "Reproduction" tab**, same gating pattern as the existing "Chaleurs" tab (content hidden + `alert-info` message when `sterilise === 'Oui'`, tab itself always visible — not gated by sex, matching how Chaleurs already behaves). Privacy: `matings` deliberately excluded from `petSnapshot()` (vet share links, household access) since it can carry a third party's name — same treatment as journal notes but unconditional, no `includeNotes` override.

**Real bug found and fixed during verification** (pre-existing, not new): `notification_prefs` columns are `not null default true`, but `toRow()` writes explicit `NULL` for any key missing from the client's `notifications` object — which a Postgres `not null` constraint rejects, crashing the *entire* `/api/sync/push` request (not just the notification row). Any client with the new field not yet in its cached bundle (or the smoke test's fixture, unchanged since before `medicationReminder` existed) would 500 on every sync. Fixed in `api/sync/push.js` by merging the client's `notifications` onto a schema-matching defaults object before `toRow()` — this was already exploitable via `medicationReminder` (Jalon C), just never triggered until this session's regression run.

**Verified 2026-09-25:** full lifecycle in the real browser (localhost:3080, separate origin per [[project_applika_redesign_state]]'s testing convention) — add saillie → mark declared → add birth outcome → mark naissance declared → mark LOMAD declared, each step's badge/action button updating correctly; pedigree modal round-trip (grandparent registry + health notes) confirmed via `localStorage` inspection; full server round-trip (push → raw DB query → pull → reload) confirmed matings and pedigree fields survive intact. `npm run lint`/`build` clean throughout. Full `scripts/smoke-account.mjs` (79 checks, unrelated to this feature but touches the same `sync/push`/`sync/pull` code paths) reran green after the notif-defaults fix — this is the regression check that caught the bug above.

**Not done:** LOF Select's genetic test panels/show-work titles (deliberately out of scope, see above), a virtual-alliance/COI simulator, and photo attachment specific to a mating record (users can already use the existing per-pet photo album — not duplicated here).
