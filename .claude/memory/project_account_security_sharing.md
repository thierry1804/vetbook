**Verified 2026-09-25** (continuing prior work, none of this had been run or checked yet):
- `backend/scripts/smoke-account.mjs` — **79 checks, all green**, but only when the `api` container is (re)built with `SMTP_HOST=mailpit SMTP_PORT=1025` per the README's documented invocation (`SMTP_HOST=mailpit SMTP_PORT=1025 docker compose --profile mail up -d --build api mailpit`). Without that, emails fall back to console-log (correct, documented behavior) and the mail-dependent smoke-test assertions fail with misleading cascading errors (e.g. "auto-invitation refusée" appears to fail, but it's actually because the earlier change-email step's confirmation link was never delivered to Mailpit, so the email was never actually changed) — **not real bugs**, just a reminder to always start the container with the mail profile before running this test.
- Real browser (`localhost:3080`, separate origin from the user's real `127.0.0.1:3080` per [[project_applika_redesign_state]]'s testing convention): registration form → Mailpit-less console-log token → email verification → profile completion %, all worked. Share-link creation correctly rejects a local pet that was never synced to the account ("Animal introuvable. Sauvegardez d'abord vos carnets.") — working as designed.
- `npm run lint` (frontend) and `npm run build` clean.

**Two real bugs found and fixed** (same anti-pattern, both in code from the prior session, neither ever exercised until this verification pass): `backend/api/_lib/snapshot.js` (`petSnapshot()`) and `backend/api/sync/pull.js` fired several `client.query()` calls concurrently via `Promise.all`/`.map()` **on the same single pg connection** (not the pool) — node-postgres queues them internally so results were never actually wrong, but it emits `DeprecationWarning: Calling client.query() when the client is already executing a query... will be removed in pg@9.0` on every share/household-pet read and every sync pull. Fixed by converting both to sequential `await` (a single connection can't parallelize anyway, so no performance cost). Verified: 0 occurrences of the warning across a full smoke-test run afterward, all 79 checks still green.
